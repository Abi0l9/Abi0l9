## Capture integrity and limitations

| Evidence | Available | Important limit |
| --- | --- | --- |
| Public product links | Yes | A public URL demonstrates accessible presentation, not the quality of private systems |
| Automatic page thumbnails | Embedded dynamically | Externally rendered, not archived or independently pixel-checked |
| Technical case studies | [Yes](../README.md) | Some evidence comes from private source inspection |
| Architecture diagrams | [Yes](../architecture/README.md) | Simplified diagrams, not production topology |
| Permanent, reviewed screenshots | **Not yet** | No authenticated or personal data should be published |
| Verified automated test output | **Not yet** | A test script in a repository is not proof that its last run passed |

### Requirements for a permanent image archive

For each future screenshot: capture an actual running public or authorized demo application; verify the image is readable at desktop and mobile widths; mask names, messages, email addresses, identifiers and private business information; record the public source URL and capture date; and save the approved image under this portfolio's assets.

Do **not** use AI-generated interface mockups, unrelated stock photos, third-party product screenshots, or a private dashboard with real customer data as evidence of shipped work.
